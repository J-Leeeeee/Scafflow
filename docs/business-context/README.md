# Scafflow — Business Context for Agents

**Purpose:** Give future agents and collaborators a clear, non-technical picture of what Scafflow is and why it exists. Use this folder when starting a greenfield rebuild or making product decisions.

**What this is not:** These documents deliberately avoid implementation details, APIs, databases, or references to how the previous prototype was built. For technical history, see `docs/project-context/` in the legacy repo.

---

## How to Use

1. Read **01–03** first for the problem, audience, and core learning model.
2. Read **04–05** to understand learner profiles and the student journey.
3. Read **06–07** for differentiation, principles, and scope boundaries.

When building or designing, treat these as the **source of truth for product intent**. If a technical choice conflicts with a principle here, flag it before implementing.
